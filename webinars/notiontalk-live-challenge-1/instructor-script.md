## PART 1. 데이터베이스와 템플릿 (0:15~0:35)

### 13. PART 1 표지

> PART 1입니다. 같은 모양의 기록을 모으는 데이터베이스, 그리고 새 페이지마다 같은 틀을 채워 주는 템플릿이에요. 실습실의 학생 명렬표, 출결 기록, 주간 업무 템플릿 실습 DB를 쓰겠습니다.

### 14. 어떤 속성을 쓸까요?

> 데이터베이스는 같은 모양의 기록을 모으는 표예요. 이 표의 칸 하나하나를 **속성**이라고 부릅니다.
>
> 하나만 고르면 선택, 여러 개면 다중 선택, 했다 안 했다는 체크박스, 날짜는 날짜 속성이죠. 오늘 특히 중요한 건 다른 DB와 연결하는 **관계형**, 누르면 일을 하는 **버튼**, 계산해 주는 **수식**입니다. 속성을 잘 설계해 두면 템플릿, 버튼, 자동화가 모두 이 위에서 움직여요.

### 15. 예시: 출결 DB 설계하기

> 오늘은 **출결 DB 하나**로 템플릿, 버튼, 자동화까지 쭉 이어 갈 거예요.
>
> 속성은 내용, 학생명렬DB, 유형, 날짜, 교시, 서류. 유형에는 병결, 병조퇴, 병지각, 체험학습을 넣었고요. 제목인 내용 칸은 지금은 비워 두세요. PART 3에서 자동으로 채워지게 만들 거예요.

### 16. 학생 명렬표 DB와 관계형으로 연결하기

**[노션]** 실습실의 출결 기록 DB 화면

> 관계형으로 연결하면 학생 페이지 하나에서 그 학생의 출결 기록을 모두 볼 수 있어요.
>
> 실습실에는 이미 연결해 두었으니 확인만 해 볼게요. 출결 기록에서 학생 칸을 누르고 학생을 골라 주세요. 그리고 학생 명렬표에서 그 학생을 열면, 방금 연결한 출결 기록이 보이죠? 이게 **양방향 연결**입니다.
>
> 참고로 관계형이 없어도 자동화는 됩니다. 학생별로 모아 보고 싶을 때 연결하는 거예요.

### 17. 보기 만들기와 내 업무로 바꾸기

### 18. 템플릿은 같은 틀과 기본값 자동 채우기

> 이제 템플릿입니다. 템플릿은 **가장 기본적인 자동화**예요. 새 페이지를 만들 때마다 같은 틀과 기본값이 한 번에 준비되거든요.
>
> 혹시 지난주 페이지를 복사해서 내용 지우고 다시 쓰신 적 있으세요? 그 페이지가 바로 템플릿 후보입니다.

### 19. 템플릿으로 할 수 있는 4가지

> 템플릿으로 할 수 있는 건 네 가지예요. 본문 틀 넣기, 속성 기본값 정하기, 기본 템플릿 지정하기, 그리고 반복 생성.
>
> 특히 반복 생성을 쓰면 매주 월요일 아침에 이번 주 업무 페이지가 이미 만들어져 있어요. 새로 만들기 옆 화살표, 템플릿 옆 점 세 개, 반복에서 정합니다.

### 24. 방법 ① 버튼 블록: DB 밖에서 페이지 추가하기

**[노션]** 실습실의 버튼 연습 공간에서 시연

> 이제 버튼이에요. 실습실 빈 공간에 **/버튼**을 입력해 주세요. 이름은 "병결".

### 25. 방법 ② DB 버튼 속성: 학생 줄마다 버튼 두기

### 26. 버튼 블록 vs DB 버튼 속성

### 27. 템플릿과 무엇이 다른가요? (블록 입력 자동화)

### 28. 블록 삽입 버튼 만들기

> /버튼, 새 작업에서 **블록 삽입**, 위치를 고르고, 넣을 블록을 평소처럼 적어 주세요. 예를 들어 "과목·차시, 잘된 점, 아쉬운 점, 다음 시간에 이어갈 것".
>
> 팁 하나 드리면, 위치를 **버튼 아래**로 하면 최신 기록이 늘 위에 쌓여요. 그리고 블록 삽입에는 수식을 쓸 수 없다는 것도 기억해 주세요.

**[실습]** 3분

### 29. 페이지 버튼 vs 데이터베이스 버튼

> 세 번째는 버튼으로 DB 값을 고치고 입력하는 거예요. 페이지 버튼은 본문에 하나, DB 버튼은 모든 행에 하나씩 생겨요. 그 행의 상태를 바꾸거나 후속 업무를 만들 때는 DB 버튼을 씁니다.

### 30. 버튼으로 할 수 있는 일

> 속성 편집, 다른 DB에 페이지 추가, 알림 보내기, 확인 창 띄우기까지는 무료로 다 돼요. 메일 보내기와 웹훅만 유료입니다. 확인 창은 실수로 누르는 걸 막아 줘서 꼭 같이 쓰시길 추천해요.

### 31. 업무 시작 / 업무 완료 버튼

> 업무 DB에 시작 버튼과 완료 버튼 두 개만 있어도 좋아요. 시작을 누르면 상태는 진행 중, 시작일은 오늘. 완료를 누르면 확인 창이 뜨고 상태는 완료, 완료일은 오늘. 클릭 한 번에 속성 세 개가 같이 바뀝니다.

## PART 3. 데이터베이스 자동화 (1:00~1:15)

### 33. PART 3 표지

> PART 3, 데이터베이스 자동화입니다. 이번엔 누르지 않아도 트리거가 생기면 노션이 대신 해 주는 "조건 스위치"예요. 실습실의 업무 연습 DB와 출결 기록 DB를 씁니다.

### 34. 자동화의 기본 공식: 트리거 → 동작

> 공식은 딱 하나예요. **트리거, 언제? 그리고 동작, 무엇을?**
>
> 예를 들면 트리거는 "상태가 완료로 바뀌면", 동작은 "완료 확인에 체크하기". 버튼은 직접 누르는 스위치, DB 자동화는 조건이 생기면 작동하는 스위치예요.

### 35. 요금제와 권한을 먼저 확인하세요

> 여기서 꼭 말씀드릴 게 있어요. 일반적인 DB 자동화를 만들고 편집하려면 **플러스 요금제 이상**이 필요합니다.
>
> 무료 요금제 선생님들은 걱정하지 마세요. 자동화가 들어 있는 템플릿을 복제하거나 초대받으면 그대로 쓸 수 있고요, 오늘은 제 시연을 보면서 트리거와 동작을 설계해 보시고, 실제로는 PART 2에서 만든 버튼으로 같은 흐름을 만들면 됩니다.

### 36. 첫 실습: 업무 완료 확인하기 (시연)

**[노션]** 업무 연습 DB에서 시연

> 업무 연습 DB 오른쪽 위 번개 모양을 눌러 새 자동화. 트리거는 상태가 완료로 바뀔 때, 동작은 완료 확인 체크. 만들기를 누르고, 가정통신문 보내기 상태를 완료로 바꿔 볼게요. 체크가 저절로 생겼죠?
>
> 하나 주의할 점, 상태를 다시 시작 전으로 돌려도 체크는 자동으로 풀리지 않아요.

### 37. 출결 제목 자동 입력하기

> 아까 PART 2에서 버튼으로 만든 "내용 입력", 기억나시죠? 이번엔 그걸 자동화로 바꿔 볼게요.
>
> 트리거는 **페이지 추가**, 동작은 **내용 칸에 수식**. 수식은 버튼 때랑 같은데, This page 자리에 **페이지 실행**이 들어가요. 그리고 "편집된 모든 속성" 트리거를 하나 더 넣으면 나중에 학생이나 유형을 고쳐도 제목이 다시 맞춰집니다.

### 38. DB 자동화와 버튼, 언제 무엇을 쓸까요?

> 정리할게요. 페이지 추가, 편집처럼 **반복되는 일은 DB 자동화**, 확정이나 마감 처리처럼 **원할 때 한 번 실행하는 일은 버튼**이에요. 이 기준만 있으면 챌린지에서 어떤 기능을 쓸지 쉽게 정하실 수 있어요.

| 복제 버튼이 안 보여요 | 노션에 로그인되어 있는지 확인해 주세요. 휴대폰보다 컴퓨터에서 여는 게 편해요. |
| 실습실 DB 관계형이 비어 있어요 | 복제본 안의 학생 명렬표를 가리키는지 확인하고, 아니면 관계형 칸에서 다시 연결해 주세요. |
| 수식에 빨간 오류가 나요 | 수식 속 속성 이름과 실제 속성 이름이 같은지, This page를 목록에서 골라 넣었는지 확인해 주세요. |
| 번개 모양(자동화)이 안 보여요 | 무료 요금제이거나 DB 권한이 없을 수 있어요. 오늘은 버튼으로 같은 흐름을 만들어 보세요. |
| 버튼을 여러 번 눌렀더니 기록이 중복됐어요 | 연습용 행은 지워도 괜찮아요. 실제로 쓸 때는 확인 창을 함께 넣어 주세요. |
| 챌린지는 무료 요금제로도 할 수 있나요? | 네. 템플릿과 버튼은 무료로 충분하고, DB 자동화는 버튼으로 대신할 수 있어요. |
