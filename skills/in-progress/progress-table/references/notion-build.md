# 진도표를 노션으로 만들기

완성된 진도표(차시 순번 기준)를 노션 DB로 옮긴다. 노션으로 두면 학사일정이 바뀔 때 그 차시의 날짜만 고치면 되고, 반별 달력 보기로 각 반의 진행을 한눈에 볼 수 있으며, 앞서 만든 평가 DB와 같은 워크스페이스에서 연계된다.

## 만들기 전 확인

교사에게 보여 주고 승인받는다.

1. 새 DB를 만들지, 기존 진도표 DB에 추가할지
2. 만들 위치(부모 페이지). 정하지 않으면 비공개 초안으로 만들고 나중에 옮길 수 있다고 안내한다
3. 속성 목록과 반 목록(반 수만큼 날짜 열이 생긴다)
4. 만들 뷰 목록

## 왜 "차시 순번 = 행"인가

진도 내용(단원·쪽·성취기준·평가)은 반과 무관하게 한 벌이다. 그래서 **행 하나 = 차시 하나**로 두고, 반별 날짜는 열로 붙인다. 이렇게 하면 내용은 한 번만 적고, 반마다 그 차시가 며칠에 걸리는지는 날짜 열로 관리한다. 학사일정이 바뀌면 해당 반의 날짜 열만 고치면 된다.

## 속성 설계

반 목록이 `1반, 2반, 3반`이면 날짜 열 세 개(`1반 날짜`, `2반 날짜`, `3반 날짜`)를 만든다. 반 수에 맞춰 늘리거나 줄인다.

| 구분 | 속성 | 타입 |
| --- | --- | --- |
| 진도 내용 | 내용(제목), 순번, 단원, 교과서 쪽, 성취기준, 평가·비고 | title / number / select / rich_text / multi_select / rich_text |
| 반별 날짜 | `<반> 날짜` (반 수만큼) | date |
| 진행 확인 | `<반> 완료` (반 수만큼, 선택) | checkbox |

`순번`은 정렬용 숫자다. 제목(`내용`)에는 "1단원 3차시: 마름모의 성질"처럼 그 차시에 배우는 내용을 적는다.

### SQL 예시 (반 3개)

```sql
CREATE TABLE (
  "내용" TITLE,
  "순번" NUMBER,
  "단원" SELECT('1단원':blue, '2단원':green, '3단원':orange),
  "교과서 쪽" RICH_TEXT,
  "성취기준" MULTI_SELECT(),
  "평가·비고" RICH_TEXT,
  "1반 날짜" DATE,
  "2반 날짜" DATE,
  "3반 날짜" DATE
)
```

성취기준 옵션은 교사가 준 코드로 채운다. 자료가 없으면 빈 multi_select로 두고 나중에 추가한다. 쪽수·단원명은 교사 자료에서만 넣는다(지어내지 않는다).

## 행 채우기

`scripts/schedule.py`의 출력이 반별 `차시 ↔ 날짜`를 준다. 이를 그대로 옮긴다. 한 행(차시)에 반별 날짜를 함께 채운다.

- `순번` = 차시 번호, `내용` = 마스터 진도표의 그 차시 내용
- `1반 날짜`/`2반 날짜`/`3반 날짜` = 스크립트가 계산한 각 반의 그 차시 날짜
- 시험·행사 주는 진도 행이 아니므로 넣지 않는다(진도표 상단 콜아웃이나 별도 메모로 남긴다)

## 만들 뷰

| 뷰 | 타입 | 설정 |
| --- | --- | --- |
| 진도 순서 | table | `SORT BY "순번" ASC`. 내용·단원·쪽·성취기준·평가·반별 날짜 SHOW. `FREEZE COLUMNS 2` |
| 1반 달력 | calendar | `CALENDAR BY "1반 날짜"` |
| 2반 달력 | calendar | `CALENDAR BY "2반 날짜"` |
| 3반 달력 | calendar | `CALENDAR BY "3반 날짜"` |

반별 달력 뷰는 반 수만큼 만든다. 한 뷰는 날짜 속성 하나만 기준으로 삼으므로, 반마다 별도 달력이 필요하다.

## 반별 누적 현황

특정 날짜 기준 반별 누적 차시(격차)는 `schedule.py`가 계산한다. 이를 진도표 페이지 상단 콜아웃이나 별도 표로 적어 둔다. 노션 안에서 자동 집계가 필요하면, 각 반 날짜가 오늘 이전인 행을 세는 롤업·수식을 더할 수 있으나, 반별 달력 뷰만으로도 진행 위치는 충분히 보인다.

## 여러 과목·반을 한 DB에 (반별·과목별·누적 보기)

한 교사가 여러 과목·여러 반을 한 곳에서 관리하고 **반별·과목별·누적 시수별**로 나눠 보고 싶으면, 위의 "차시=행, 반=날짜 열" 대신 **행 하나 = 한 번의 수업(과목·반·차시)** 모델이 뷰를 만들기 쉽다. 내용이 반마다 조금 중복되지만, 그룹핑만으로 세 가지 보기가 바로 나온다.

| 구분 | 속성 | 타입 |
| --- | --- | --- |
| 분류 | 과목, 반 | select |
| 진도 | 내용(제목), 순번(차시), 단원, 교과서 쪽, 성취기준 | title / number / select / rich_text / multi_select |
| 시간 | 날짜, 누적차시 | date / number |
| 기타 | 평가·비고, 완료 | rich_text / checkbox |

`누적차시`는 그 반에서 그 수업이 몇 번째인지로, `scripts/schedule.py`가 계산한 차시 번호를 넣는다.

뷰 세 개:

| 뷰 | 타입 | 설정 |
| --- | --- | --- |
| 반별 보기 | table | `GROUP BY "반"`, `SORT BY "날짜" ASC` |
| 과목별 보기 | table | `GROUP BY "과목"`, `SORT BY "순번" ASC` |
| 누적 시수별 보기 | table | `GROUP BY "반"`, `SORT BY "누적차시" ASC`, 누적차시·날짜 강조 |

## 만든 뒤 안내

1. DB URL과 뷰(진도 순서 + 반별 달력)의 용도
2. 학사일정이 바뀌면 그 차시 행의 해당 반 날짜만 고치거나, `schedule.py`로 다시 계산해 이후 날짜를 갱신
3. 앞서 만든 평가 DB와 같은 워크스페이스에 두면 과목·차시 단위로 연계된다
